The Brief 
Your portfolio will document a series of three code experiments that demonstrate a variety of creative code techniques and variations. The portfolio will take the form of a public GitHub repository, put the live and edit links. You can use canva to make the portfolio.
 It is expected you will create your experiments in P5.js. You may submit one of your three experiments as a TouchDesigner project. Use of other technologies must be agreed with your tutor before you start work using them.

Your code experiments will respond to three of the following themes. 
Pick one experiment from each list
Experiment 1
An alternative visual way to represent a realtime clock
A real time audio visualiser, with 4 different effects
A data visualiser with some animated effect when data or view changes 
Experiment with the moire effect. Create 3 variations or experiments that change over time or change with the mouse.

Experiment 2
Alternative pixels – display pixel data from the webcam in at least 3 ways that are not pixels, or directly coloured squares. 
A city or landscape generator, with at least 3 distinct types of building or land. 
Mouse disturber - a 'force field' from the mouse changes or moves an arrangement of shapes when the mouse is near or over them. Create three different variations of behaviour.
A mouse-driven painting tool with 4 different 'brush' tools 

Experiment 3
Use of pose detection or image classifier to drive some interesting visual behaviour (techniques will be shared in Week 11)
concrete poetry project 
An animated, progressive text display, that reveals a poem or block of text over a period of time in some interesting way
An autonomous pattern generator that will create a rich visual effect that is different each time it is run (think Tyler Hobbs - Fidenza)
one key game (two players) with a clear win state 

You may propose an alternative experiment for one of the categories, but you must receive approval from the tutor before starting work on this.
The starting point could be from a class demo, or an example or a tutorial found elsewhere, or the work of an artist. The work must be your own and must be a significant development from this starting point, demonstrating both technical and creative development. You will need to be able to explain how the code works if challenged to do so. Failure to do so could result in an unfair practice procedure.

Clarity on original code
Up to 30% of each experiment's code can be taken from a class or online tutorial, or some other source of an initial technique, such as AI.​ The remaining code must be your own work, experimenting from this base, developing your ideas and how things behave, or are visualised.​ The source of code that is not your own must be acknowledged in a comment in your code and in the text in your portfolio, with a link where appropriate.​ Submission of code that is not your own work will result in the academic misconduct policy being invoked.​
Each experiment will be in a folder in your github repo, linked from a readme file that explains the underlying techniques, with links to some early p5.js experiments. 


Each experiment should demonstrate: 
Use of creative coding techniques, language features and computational thinking 
Creative experimentation with techniques and outcomes beyond the basic tutorial or early experiments, showing a combination of intent and experimentation. 
A variety of output variations achieved through changes to the code and input conditions, actions, and/or data. 
(where appropriate) the influence of chance, time and changes on outcomes. 
An understanding of the cause and effect of changes made between variations 
Each entry should link to a series of live versions of the code and include screenshots and approximately 300 words of commentary. This commentary should describe the code techniques and creative explorations that you have used. Declare the starting point or inspiration for the work, for example, an in-class demo, an online tutorial, or the work of an artist. Describe the development process, your experiments and talk about what worked, what didn't, and how you resolved problems. Include a critical self-reflection. 
It is recommended that these are created in p5.js or other languages used in class. You may use other coding languages only by prior agreement with your tutor.
